# 豆包账号池新手使用手册

本手册面向第一次使用豆包账号池、不会写代码，或者需要把它连接到无限画布、自动化工作流的用户。

当前版本：`0.1.72`

## 0. 五分钟快速接通

第一次使用只做下面几步：

1. 安装并打开软件，添加一个账号，在独立豆包窗口中手动登录。
2. 返回账号池点击“检测”，确认账号显示“已登录、空闲”。
3. 在“配置管理”开启本地 API 和后台自动执行，确认端口为 `17888`，填写 API Key 和去水印 Token，然后保存。
4. 在终端执行 `curl http://127.0.0.1:17888/health`，确认返回 `ok: true`。
5. 在无限画布 HTTP 节点中设置生成地址 `http://127.0.0.1:17888/api/generate`，请求头设置 `Authorization: Bearer 你的APIKey`。
6. 提交后保存返回的 `requestId`，每 3 到 5 秒查询 `/api/requests/{requestId}`。
7. 只有状态变成 `success` 后，才把 `cleanVideoUrl` 或 `outputVideoPath` 交给画布的视频节点。

先用一条无参考图的 Mini 测试任务跑通，再添加参考图和多账号并发。建议使用 AI/Codex 等能调用本地 HTTP API 的客户端连接无限画布，不要让客户端直接控制豆包窗口或系统剪贴板。

## 1. 先理解它是做什么的

豆包账号池不是视频模型，也不是另一个豆包客户端。它承担四件事：

1. 为每个豆包账号保存独立登录环境，避免 Cookie 和登录状态串号。
2. 接收无限画布或其他程序发来的本地 HTTP 请求。
3. 自动选择一个已登录、空闲且额度足够的账号，在豆包网页提交视频任务。
4. 等待视频完成、复制豆包分享地址、调用去水印服务，最后只把真实 MP4 结果交给调用方。

完整流程：

```text
无限画布提交任务
  -> 豆包账号池返回 requestId
  -> 自动选择账号并提交豆包
  -> 等待豆包生成
  -> 复制分享地址（只作为内部解析输入）
  -> 去水印并验证 MP4
  -> 无限画布取得 cleanVideoUrl 或 outputVideoPath
```

无限画布不应接收或保存 `doubao.com/chat/...`、`doubao.com/thread/...` 分享页面。只有真实 MP4 才是最终结果。

## 2. 安装

从 GitHub Releases 下载与系统对应的安装包：

- Apple Silicon Mac（M1/M2/M3/M4）：ARM64 DMG。
- Windows 10/11 64 位：Windows x64 EXE。

当前安装包没有商业代码签名：

- macOS 首次打开可能提示无法验证开发者。尝试打开一次后，进入“系统设置 -> 隐私与安全性 -> 仍要打开”。
- Windows 可能显示 SmartScreen，确认文件来自本项目发布页后选择继续运行。

升级只替换应用程序，不会自动删除账号数据。不要删除系统中的 `doubao-account-manager` 数据目录，除非确实要清空全部账号和登录状态。

## 3. 第一次使用：添加豆包账号

1. 打开“豆包账号池接口服务”。
2. 点击“添加账号”。程序会自动建立独立分区，例如 `persist:doubao_account_001`。
3. 在弹出的豆包窗口中手动登录。验证码、扫码和安全验证由用户本人完成。
4. 登录完成后关闭豆包窗口或返回账号池。
5. 点击该账号的“检测”，确认显示“已登录”和“空闲”。
6. 添加第二个账号时重复以上步骤，不要把一个账号的 Cookie 手工复制给另一个账号。

账号备注只是帮助自己识别账号，不影响登录和调度。账号名称、历史对话标题和提示词都不能代替任务 ID。

## 4. 额度怎样计算

默认每个账号每天维护一条本地共享额度：

| 项目 | 默认值 |
| --- | ---: |
| 每日总额度 | 10 |
| Mini 单次消耗 | 2 |
| Fast 单次消耗 | 3 |

因此一个满额账号最多可生成 5 次 Mini，或 3 次 Fast（剩余 1 点）。Mini 和 Fast 显示的是两种“全部用于该模型”的预计产能，不能相加。

注意：界面额度是本地调度账本，不是豆包官方实时余额。如果用户在豆包网页中手动生成了视频，本地额度不会自动知道，需要在账号设置中校正或重置。

## 5. 推荐配置

进入“配置管理”，至少确认以下项目：

| 配置 | 建议 |
| --- | --- |
| 开启本地 API 服务 | 开启 |
| 端口 | 默认 `17888` |
| API Key | 修改默认值并妥善保存 |
| 后台自动执行接口请求 | 开启 |
| 调试时显示豆包执行窗口 | 正常使用关闭，排错时开启 |
| 完成后自动关闭执行窗口 | 开启 |
| 生成超时 | 建议 900 秒 |
| 最大并发账号数 | 不超过当前可用账号数 |
| 去水印接口 Token | 按去水印服务要求填写 |
| 输出目录 | 可选；填写后会额外保存本地 MP4 |

保存配置后，如顶部 API 状态没有恢复为绿色，点击“重启 API”。

## 6. 先检查 API 是否正常

在本机终端执行：

```bash
curl http://127.0.0.1:17888/health
```

返回内容中应包含：

```json
{
  "ok": true,
  "service": "doubao-account-pool"
}
```

如果健康检查失败，先确认软件正在运行、API 已开启、端口没有被其他程序占用。

## 7. 无限画布怎样连接

### 7.1 画布和账号池在同一台电脑

在无限画布的 HTTP/API 节点中填写：

| 项目 | 内容 |
| --- | --- |
| Base URL | `http://127.0.0.1:17888` |
| 生成接口 | `POST /api/generate` |
| 查询接口 | `GET /api/requests/{requestId}` |
| Header | `Authorization: Bearer 你的APIKey` |
| Content-Type | 无参考图可用 JSON；上传图片用 multipart/form-data |

建议的画布节点映射：

| 画布数据 | 接口字段 |
| --- | --- |
| 视频提示词 | `prompt` |
| 模型选择 | `model` |
| 参考图片 | `referenceImage` 或 `referenceImageUrl` |
| 画布任务来源 | `source` |
| 画布回调接口 | `callbackUrl` |
| 返回的任务编号 | 保存为 `requestId` |
| 最终视频 | `cleanVideoUrl` 或 `outputVideoPath` |

### 7.2 画布不在同一台电脑

`127.0.0.1` 永远表示“当前程序自己所在的电脑”。如果无限画布运行在云端、Docker、另一台电脑或远程服务器，它访问的 `127.0.0.1` 不是这台 Mac。

这种情况需要建立安全的 HTTPS 反向代理或隧道，并保护 API Key。不要直接把本地端口无认证暴露到公网。Docker 中通常需要改用 `host.docker.internal`，具体取决于画布的运行环境。

如果终端 `curl` 正常、浏览器画布却请求失败，常见原因是浏览器 Mixed Content 或 Private Network Access 限制。优先让画布后端发送请求，不要只依赖浏览器前端直接访问本机 HTTP。

## 8. 提交一个无参考图任务

```bash
curl -X POST http://127.0.0.1:17888/api/generate \
  -H "Authorization: Bearer local-doubao-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "seedance_2_0_mini",
    "aspectRatio": "16:9",
    "prompt": "生成一段10秒、16:9横屏的女性科普动画，不要字幕，不要水印。",
    "source": "infinite-canvas"
  }'
```

模型只能使用：

- `seedance_2_0_mini`
- `seedance_2_0_fast`

当前接口支持独立的 `aspectRatio` 字段，账号池会在豆包窗口中选择并校验 `9:16` 或 `16:9`。时长仍建议写入提示词，最终结果以豆包实际生成状态和 MP4 文件为准。

## 9. 提交参考图

推荐直接上传图片文件：

```bash
curl -X POST http://127.0.0.1:17888/api/generate \
  -H "Authorization: Bearer local-doubao-key" \
  -F "model=seedance_2_0_mini" \
  -F "prompt=参考图中的人物和产品，生成10秒、16:9横屏动画。" \
  -F "referenceImage=@/Users/你的名字/Pictures/reference.png" \
  -F "source=infinite-canvas"
```

也可以使用：

- `referenceImagePath`：账号池所在电脑能够访问的绝对路径。
- `referenceImageUrl`：账号池能够直接下载的图片 URL。

画布在云端时不能把云端自己的本地路径传给 Mac；应上传文件本身，或提供 Mac 可以访问的 URL。

## 10. 画布必须保存 requestId

提交成功首先返回 HTTP `202` 和状态 `accepted`，这不代表视频已经生成。画布必须保存返回的 `requestId`，例如：

```json
{
  "requestId": "doubao-1234567890abcdef",
  "status": "accepted",
  "message": "已接收，已进入执行队列",
  "cleanVideoUrl": null,
  "outputVideoPath": null
}
```

即使三个任务名称和提示词完全相同，也必须通过各自的 `requestId` 区分。不要用提示词、豆包对话名称或账号名称判断任务。

## 11. 轮询任务状态

无限画布应每 3 到 5 秒查询一次：

```bash
curl http://127.0.0.1:17888/api/requests/doubao-1234567890abcdef \
  -H "Authorization: Bearer local-doubao-key"
```

状态处理规则：

| 状态 | 画布应怎样处理 |
| --- | --- |
| `accepted` | 显示排队中，继续查询 |
| `running` | 显示生成中或解析中，继续查询 |
| `success` | 读取 MP4 结果并结束轮询 |
| `failed` | 显示 `message`，停止轮询 |
| `stopped` | 显示已停止，停止轮询 |

只有 `status: "success"` 时才读取最终结果：

```json
{
  "status": "success",
  "cleanVideoUrl": "https://example.com/final-video.mp4",
  "outputVideoPath": "/Users/name/Movies/doubao-output/doubao-xxx.mp4"
}
```

`outputVideoPath` 只有账号池和画布在同一台电脑且配置了输出目录时才适合直接使用。远程画布应下载 `cleanVideoUrl`。部分 CDN 地址可能有有效期，画布拿到成功结果后应尽快保存视频。

## 12. 使用回调，而不是一直轮询

如果无限画布提供可接收 POST 的后端地址，可在生成请求中传入：

```json
{
  "callbackUrl": "http://127.0.0.1:3000/doubao/callback"
}
```

账号池会多次发送状态更新。画布应按 `requestId` 更新同一条任务，不要每收到一次回调就创建一个新任务。收到 `success`、`failed` 或 `stopped` 后结束该任务。

纯浏览器画布通常没有可接收回调的服务器，此时使用轮询更简单。

## 13. 建议的 AI/Codex 接入方式

如果你使用 AI、Codex 或其他自动化客户端操作无限画布，建议把账号池当作本机视频服务：

1. 客户端读取本项目的 `docs/API.md`，调用 `/api/generate`，并把 `requestId` 写入画布任务。
2. 客户端按 `requestId` 查询状态或接收回调，显示接口返回的 `message`，这样豆包的违规、确认、超时和去水印错误会直接回传，不需要逐个打开豆包窗口排查。
3. 只有 `success` 且有 MP4 结果时才创建或更新画布视频节点；失败任务保留错误信息，不要把分享页链接当视频。
4. 参考图使用 multipart 文件上传、可访问的绝对路径或 URL；不要复制登录信息、Cookie 或本地数据库到画布项目或 Git。

推荐的画布任务字段：`requestId`、`source`、`model`、`aspectRatio`、`prompt`、`status`、`message`、`cleanVideoUrl`、`outputVideoPath`。即使任务提示词或名称相同，也始终以 `requestId` 区分。

## 14. 什么时候使用“恢复结果”

如果豆包中已经看到了生成完成的视频，但任务因为分享链接或去水印暂时失败，不要重新提交 `/api/generate`，否则可能重复生成并再次消耗额度。

使用原来的 `requestId` 调用：

```bash
curl -X POST \
  http://127.0.0.1:17888/api/requests/doubao-1234567890abcdef/retry-result \
  -H "Authorization: Bearer local-doubao-key"
```

恢复结果只查找已有视频、重新复制分享地址并去水印，不会再次提交视频生成，也不会重复扣除本地额度。

## 15. 多账号和并发

- 不同账号可以并行执行。
- 同一个账号的任务必须排队，避免同时操作同一豆包页面。
- 实际并发数取“最大并发账号数”和“当前可用账号数”中的较小值。
- 4 个已登录且有额度的账号，最大并发设置为 4 时，最多可以同时运行 4 个视频任务。
- 运行中的账号不要同时由用户手工切换页面、发送消息或修改生成设置，否则会干扰自动操作。

## 16. 接口日志与行动日志怎么看

“接口日志”用于看任务最终状态、提示词、参考图、结果和错误信息。

“行动日志”用于定位程序实际执行到了哪一步，例如：

- 是否分配了账号。
- 是否上传参考图。
- 是否成功提交豆包。
- 是否识别到视频生成完成。
- 是否打开分享面板并复制地址。
- 去水印第几次解析、耗时多久。

行动日志默认保留 3 天并自动清理。排错时请提供 `requestId` 和该任务的行动日志，不要只提供提示词或豆包对话标题。

## 17. 常见问题

### API 状态不是绿色

确认 API 已开启，端口没有冲突，然后保存配置并点击“重启 API”。使用 `/health` 再检查。

### 返回 401 Unauthorized

调用方的 Bearer Token 与配置管理中的 API Key 不一致。

### 返回 409，没有可用账号或额度不足

检查是否有账号已登录、空闲，并且共享额度足够。Mini 至少需要 2 点，Fast 至少需要 3 点。

### 一直显示 accepted

通常是“后台自动执行接口请求”没有开启，或者任务正在同账号队列中等待。

### 豆包已经有视频，接口仍失败

先查看行动日志。如果失败发生在分享或去水印阶段，使用原 `requestId` 调用恢复结果，不要重新生成。

### 去水印很慢，第二次才成功

豆包分享页和视频资源可能异步准备。程序会验证 MP4 并短间隔重试。只有得到真实可播放视频才返回成功；平台不支持或始终没有 MP4 时必须返回失败。

### 画布拿到了链接但无法播放

确认字段是 `cleanVideoUrl`，而不是豆包聊天页或分享页。拿到成功结果后尽快下载；如仍失败，查看行动日志中的 MP4 验证和 HTTP 状态。

### 输出比例不符合 16:9

当前 API 没有结构化比例控件，比例要求来自提示词，豆包可能不完全遵守。请在提示词开头和结尾明确写“16:9 横屏”，并检查参考图本身是否为竖图。

### 同样提示词的任务会不会串

画布按 `requestId` 区分任务，程序优先记录正式豆包对话地址。不要通过重复的对话标题或提示词寻找任务。

## 18. 使用注意事项

- 软件必须保持运行，电脑不能在任务执行期间休眠或断网。
- 不要在账号忙碌时手工操作该账号的豆包窗口。
- 不要删除系统数据目录来升级软件；升级应用不会清除登录状态。
- 不要把 API Key、Cookie、SQLite 数据库或账号分区上传到 GitHub。
- 不要把 `127.0.0.1` 地址直接提供给云端画布，云端访问不到本机回环地址。
- 不要把 `accepted` 当作成功；必须等待 `success`。
- 不要把豆包分享地址当作最终视频；最终结果必须是可播放 MP4。
- 不要在恢复结果可以解决时重复提交生成任务。
- 程序不处理自动注册、验证码绕过或平台限制规避。

## 19. 新手检查清单

正式运行前逐项确认：

- [ ] 软件顶部显示 API 正常。
- [ ] 至少一个账号显示“已登录、空闲”。
- [ ] 账号剩余额度足够。
- [ ] 已修改并记录 API Key。
- [ ] 后台自动执行已开启。
- [ ] 去水印接口和 Token 已配置。
- [ ] 无限画布与账号池在同一台电脑，或已经配置安全代理。
- [ ] 画布保存 `requestId`，并按状态轮询或接收回调。
- [ ] 画布只在 `success` 时读取 `cleanVideoUrl` 或 `outputVideoPath`。
- [ ] 先用一条测试任务跑通完整流程，再批量并发。

更完整的字段说明见 [API.md](API.md)。
